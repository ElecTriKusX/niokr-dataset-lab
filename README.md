# niokr-dataset-lab

Исследовательская лаборатория формирования, автоматической разметки и оценки качества датасетов для декомпозиции научно-исследовательских и опытно-конструкторских работ (НИОКР).

## Архитектура

Python 3.10+, SQLite, без сторонних библиотек. `niokr.py` — единственная точка входа в лабораторию, `gisnauka_parser.py` — адаптер источника. Параметры исследования находятся в `config.json` и `grnti_groups.json`. После импорта исходные JSON больше не нужны для вычислений.

| База в `data/` | Содержимое |
|---|---|
| `corpus.sqlite` | Все сохранённые карточки и версии НИОКТР, отчётов, РИД; исходный JSON, тексты, номера, рубрики, связи, хеши |
| `audit.sqlite` | Индекс регистрационных записей, фильтры, кластеры SimHash, сигналы Regex V1/V2, прежние исключения |
| `datasets.sqlite` | Состав пилота, обезличенные входы, Regex-фрагменты, квоты, веса, исключения из будущего теста |
| `comparison.sqlite` | Необязательное сравнение схем стратификации, дисперсии известных признаков, квоты и покрытия |

Каждая база создаётся в отдельном временном файле, проверяется `quick_check` и публикуется только после завершения. Существующая база не перезаписывается. Идентификаторы снимка корпуса и аудита связывают производные базы; номера кластеров имеют смысл только внутри конкретного аудита. Базы и результаты не коммитятся. Неизменяемость здесь — соглашение приложения, а не защита от внешнего редактирования SQLite.

В будущем отдельные базы разметки и метрик будут добавлены тогда, когда появятся соответствующие алгоритмы. Финальный Test пока не формируется.

## 1. Однократный импорт

Из уже сохранённой папки с JSON (предпочтительный вариант):

```powershell
python .\niokr.py import --root "D:\data\cards_by_folder"
python .\niokr.py status
```

Сохраняются все найденные карточки трёх типов, не только 225858 уникальных регистрационных записей старого индекса. JSON остаётся побайтово в `raw_json`. Сверьте количество файлов и сделайте резервную копию SQLite прежде, чем очищать исходную директорию. Неизвестные типы JSON не импортируются. Не следует удалять единственную исходную копию.

Новый снимок можно также загрузить напрямую через API, без промежуточных JSON (сетевой режим необходимо проверить на небольшом интервале перед полной загрузкой):

```powershell
python .\gisnauka_parser.py --from-year 2015 --to-year 2015
```

API-режим сохраняет канонически сериализованные карточки, а не исходное HTTP-тело. Он создаёт новый снимок и не восстанавливает автоматически прежний исторический набор. При сбое неполная база не публикуется; возобновление сетевой загрузки пока не реализовано.

## 2. Восстановление именно проведённого эксперимента

Если сохранены старые результаты, используйте их **один раз**, чтобы сохранить порядок индекса и идентификаторы кластеров. Путь к архиву замените на ваш.

```powershell
python .\niokr.py audit `
  --index "D:\archive\grnti_sampling_full\10_population_index.csv" `
  --manifest "D:\archive\grnti_sampling_full\11_manifest.json" `
  --previous-review "D:\archive\grnti_sampling_full\06_review_index.csv"

python .\niokr.py pilot --verify "D:\archive\11_pilot_index.zip"
python .\niokr.py status
```

Первая команда проверяет карточки старого индекса по номеру, хешу текста и рубрикам, сохраняет старые кластеры, вычисляет Regex V2 из БД и исключает прежние 800 диагностических кластеров. Вторая пересоздаёт G/E и проверяет совпадение с архивом: идентификаторы, принадлежность к группам отбора, ключи обезличивания, тексты, Regex-фрагменты и список исключений. При расхождении база не создаётся. Ожидаются рамка 214693, G=200, E=200, 5801 строгий кандидат и 1200 исключений. Это не новый Test Dataset.

Параметры исторического пилота: 10 научных групп, равные квоты, внутри групп пропорциональное распределение по периодам с минимумом 2, seed=20261124. Исходная группировка и Regex сохранены. Обновлённые параметры требуют новой базы данных (например, новый `data_dir` в отдельной конфигурации), а не перезаписи исторического пилота.

## 3. Новый аудит с нуля (для нового снимка)

```powershell
python .\niokr.py audit
python .\niokr.py pilot
```

Свежий аудит использует зафиксированные признаки V1, фильтры (250 символов, 30 слов, непустая аннотация), точные хеши, SimHash с расстоянием 3 и лимитом корзины 300, Regex V2. Выбор версии карточки и порядок обхода детерминированы, но не обязаны совпадать с историческим аудитом. Без исторического индекса не восстанавливаются прежние 800 исключений; такой запуск нельзя считать восстановлением старого пилота или независимым Test. Перед будущим тестом потребуется перенос исключений между снимками и дополнительная семантическая проверка утечек.

## 4. Экспорт входов для модели и сравнение схем

```powershell
python .\niokr.py export pilot_inputs.jsonl
python .\niokr.py compare
python .\niokr.py status
```

Экспорт — единственная штатная операция, создающая JSONL. Он содержит только обезличенный ID, название и аннотацию. Схемы сравниваются на общей рамке; выборка E в сравнении по-прежнему использует Regex V1 как прокси, как в ранее проведённом сравнительном исследовании, а не качество декомпозиции. Поддерживаются равномерные, пропорциональные и гибридные квоты. Для следующего исследования распределение Test будет определено отдельно.

## Тесты

```powershell
python -m unittest -v
```

Тесты проверяют алгоритмы квот, Regex, классификацию, импорт и защиту от публикации неполной базы, сквозной сценарий после удаления тестовых исходников. Полный локальный импорт и сетевой режим ещё требуют проверки на рабочей машине. Исторический индекс и архивы не входят в репозиторий.
